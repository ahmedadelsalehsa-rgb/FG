## 1. Story hook
Monitoring shows that many system-test defects trace back to unclear requirements and weak test cases. Reviews catch these problems before they cost a test cycle, and the review record becomes gate evidence.

## 2. Purpose & outcomes
After this chapter, the participant can:
- Choose a review type for a work product (requirements, test plan, test cases, code)
- Run a review and record findings and metrics
- Use review records as gate evidence and as a control action

## 3. Concepts
Planned scope:
- Static testing value and work products
- Review process (planning → initiation → individual review → communication & analysis → fixing & reporting)
- Review types: informal, walkthrough, technical review, inspection
- Roles and checklists
- Review records as evidence for G1 and test design
- Review metrics (defects found, effort, coverage) as monitoring input
- Reviews as a corrective/control action triggered by monitoring
