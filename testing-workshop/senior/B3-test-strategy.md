## 1. Story hook
Policy says *what* matters. For R1.0, the strategy decides *how* we test: which levels, which test types, which quality attributes, and how deep each risk area goes.

## 2. Purpose & outcomes
After this chapter, the participant can:
- Write an organisational and a project-level test strategy
- Select quality attributes (ISO 25010) and map them to test types
- Apply a risk-based approach to decide depth and techniques
- Define the automation and regression approach at strategy level

## 3. Concepts
Planned scope:
- Organisational vs project test strategy
- Test levels and responsibilities
- Quality attributes (ISO 25010): functional suitability, performance efficiency, compatibility, usability, reliability, security, maintainability, portability
- Mapping quality attributes → test types → test levels
- Risk-based approach: risk level → test depth/techniques (assessment itself done in C7)
- Entry/exit criteria framework (detailed in B5)
- Regression & automation strategy (detailed in D12)
- Test environment & data approach (detailed in S1)
